# Development log — November 2026

## 2026-11-04 — The app API's types and checks

**Done:** [ADR-0004](../decisions/0004-talking-to-the-cloud.md), and its first step: the app API's types and checks, made from ai-platform's schema. `platform/` moves to `app/v1.2`.
- **`npm run protocols`** writes them into `src/shared/protocols/generated/`: json-schema-to-typescript's types for every definition, and Ajv's standalone checks for the 15 bodies that the schema's `from_cloud` tells apart. CI runs it with `--check`, and fails if what is committed differs.
- **`received(definition, body)`**, in `shared/protocols`, gives a body as its type, or a `ProtocolError` that says where and which rule, never the value.
- **Tests:**
  - every body that ai-platform's examples have the cloud send passes;
  - the generated checks give the same verdict as Ajv compiling the schema in the test, on those bodies and on bodies planted to break its patterns and conditions;
  - three mutants of the checks all failed them.

**Decisions:** The owner left the choices of this work to the assistant, to be made for long-term development (ai-platform's dev log, 2026-11-03). ADR-0004 records them:
- checks compiled before the app runs, since Hermes does not promise the Function constructor;
- one client over a transport that is a port, with a simulated cloud;
- the refresh token in expo-secure-store, the access token in memory;
- the simulated cloud by default, and a real one named only on the machine that builds.

**Problems / unfinished:** Ajv's strict mode refuses a `then` that requires a property its parent declares, as the app API's member does, though JSON Schema allows it. The generator turns that one rule off.

**Next:** `shared/cloud`, the simulated cloud, and `account`, signing in with the development provider. Then `homes`.
