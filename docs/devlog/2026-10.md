## 2026-10-29 — Platforms and framework, proposed

**Done:** [ADR-0001](../decisions/0001-platforms-and-framework.md), proposed: React Native with Expo, in TypeScript, Android first. The owner has an Android phone and no Mac; iOS would be built in the cloud when an owner needs it.
- Set-up decided it. SPAKE2+ needs arithmetic on elliptic-curve points: noble does it in JavaScript, audited and maintained. Dart's library for it has not changed since 2025-03, and Kotlin's multiplatform one does not do it.
- Bluetooth LE: Flutter's main library needs a paid licence for for-profit use. React Native's are community projects, and one is chosen when set-up is built.
- Android's developer verification reaches every country in 2027. Installing one's own builds over ADB stays possible, and a free account covers 20 devices.
- The owner asked why set-up needs Bluetooth at all, since the robot has a screen. Set-up on the screen alone, with a code approved on the phone, was weighed and dropped. The screen and its touch layer break often on a mobile robot, and there is no camera to read a code instead. Over Bluetooth, the phone stands in for both.
- iOS is planned from the start, though not released yet. CI builds for the simulator from the first code, and App Store guideline 4.8 goes into the sign-in decision.

**Problems / unfinished:** Set-up still needs the robot's screen to show the code. ai-robot should decide how set-up survives a dead screen: the code spoken or printed, and a set-up button.

**Next:** Once the ADR is decided: the app's skeleton; then sign-in and the app ⇄ cloud protocol, in ai-platform.
