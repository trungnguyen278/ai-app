## 2026-10-29 — Platforms and framework, proposed

**Done:** [ADR-0001](../decisions/0001-platforms-and-framework.md), proposed: React Native with Expo, in TypeScript, Android first. The owner has an Android phone and no Mac; iOS would be built in the cloud when an owner needs it.
- Set-up decided it. SPAKE2+ needs arithmetic on elliptic-curve points: noble does it in JavaScript, audited and maintained. Dart's library for it has not changed since 2025-03, and Kotlin's multiplatform one does not do it.
- Bluetooth LE: Flutter's main library needs a paid licence for for-profit use. React Native's are community projects, and one is chosen when set-up is built.
- Android's developer verification reaches every country in 2027. Installing one's own builds over ADB stays possible, and a free account covers 20 devices.
- The owner asked why set-up needs Bluetooth at all, since the robot has a screen. Set-up on the screen alone, with a code approved on the phone, was weighed and dropped. The screen and its touch layer break often on a mobile robot, and there is no camera to read a code instead. Over Bluetooth, the phone stands in for both.
- iOS is planned from the start, though not released yet. CI builds for the simulator from the first code, and App Store guideline 4.8 goes into the sign-in decision.

**Problems / unfinished:** Set-up still needs the robot's screen to show the code, and its touch layer to open set-up again later. The owner turned down the code spoken or printed. A button to open set-up is still to decide, in ai-robot.

**Next:** Once the ADR is decided: the app's skeleton; then sign-in and the app ⇄ cloud protocol, in ai-platform.

## 2026-10-29 — The architecture, proposed

**Done:** [The architecture](../architecture.md) and [ADR-0002](../decisions/0002-architecture.md), proposed. The app has the shape of the robot and the cloud: modules with boundaries, checked by dependency-cruiser, and ports and adapters.
- A simulated device and a simulated cloud let set-up be built and tested before a robot or a cloud can take part.
- ai-platform's schemas give the protocols' types, and check every message, with Ajv.
- The cloud's data goes through one query cache (TanStack Query). The routes (Expo Router) only render the modules' screens.
- ADR-0001 was merged as proposed. It is accepted once the owner says so.

**Next:** The owner's decisions on ADR-0001 and ADR-0002. Then the app's skeleton, and in ai-platform the owners' sign-in, the app ⇄ cloud protocol and the catalogs' format.

## 2026-10-30 — The skeleton

**Done:** The app's skeleton, with no feature yet.
- **The stack:** Expo SDK 58 (React Native 0.88.1, React 19.3, TypeScript 6), and Expo Router with typed routes. Routes live in `app/`, and modules in `src/` (ADR-0002).
- **The configuration:** `config/base.toml`, the environment's file and a git-ignored `local.toml`. Expo checks them against `config/schema.json`, with Ajv, when it reads `app.config.ts`. The environment has no default. Development gets an identity of its own, so that it installs beside a released app.
- **The catalogs** (ai-platform ADR-0007):
  - `locales/en.json` and `vi.json`, formatted by `messageformat` 4.1;
  - messages are looked up along the phone's languages, matched by RFC 4647's lookup, then in English;
  - a message that fails falls back, and is reported without its values;
  - the system offers people the languages found in `locales/`.
- **The first screen:** `homes`, empty until sign-in exists.
- **CI:** types; ESLint with Prettier; the boundaries, with dependency-cruiser; Jest, which includes MF2's suite from the pin of ai-platform; Android's build, with JDK 17; and the iOS simulator's, unsigned, on macOS 26 with Xcode 26.6.
- **The pin of ai-platform** moved, for `catalogs/`.

**Problems / unfinished:**
- Jest has no `require.context`, so each language's file is listed in `src/shared/catalog/locales.ts`. A test checks that list against `locales/`.
- The app has not run on a phone yet. Expo Go on the owner's Android phone is the next check.
- The app's identity, `io.github.trungnguyen278.aiapp`, can change only until its first release in a store.

**Next:** In ai-platform, the owners' sign-in and the app ⇄ cloud protocol.

## 2026-10-30 — The interface, proposed

**Done:** [ADR-0003](../decisions/0003-interface-and-motion.md), proposed. The owner wants an interface rich in motion, with animation that serves the experience. The owner chose the robot's visual language, in light and dark themes.
- One tone, glowing, that follows the robot's mood, with a variant for each theme that meets WCAG 2.2 AA.
- The design is data: tokens, motion tokens and haptics.
- Motion runs on the UI thread, with Reanimated 4, Gesture Handler and Skia. With reduce motion on, movement becomes short fades.
- Be Vietnam Pro, drawn for Vietnamese.
- A studio in the app shows every component and motion.
